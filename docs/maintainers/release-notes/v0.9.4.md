# pi-web-x v0.9.4 发布说明

> 状态：**Released**。本文是已发布版本的冻结归档；发布流程见 [`../release.md`](../release.md)。

## 概要

v0.9.4 聚焦 Web 访问认证的稳定性、会话持久化语义与测试隔离：

1. **修好了滑动续期「看上去在续、实际没续」的缺陷**。页面保活虽然每分钟（后台节流后按小时）ping `/api/auth/status`，但续期中间件读不到路由层写入的刷新 Cookie，续期 `Set-Cookie` 从未真正返回浏览器——会话仍会在 24 小时后掉线。现在续期真实生效。
2. **登录/登出有了可靠的落盘语义**。此前登录成功的响应可能发生在 Session 尚未写盘之前，服务一重启登录态就丢失；登出也可能「看似成功但撤销未落盘」。现在关键写盘在响应前完成，失败明确报错。
3. **认证失效与后台 Agent 解耦**。会话过期、登出或改密后，前端只切换到登录界面，**不会**停止/中止正在运行的 Agent 任务；SSE 观察通道断线时自动补查认证状态，瞬时断网不再误判为登出。
4. **修复单元测试误重启真实服务的严重问题**。完整更新流转测回退到了真实的 `refreshRegisteredServiceAfterUpdate()`，会探测 `~/.config/systemd/user/` 并执行 `systemctl --user restart pi-web-x`——2026-08-31 运行日志中的服务 stop/restart 大部分由测试触发。现在已注入假实现，测试无法触碰真实服务管理命令。

## 新增与改进

- **滑动续期真正生效**：保活 ping `/api/auth/status` 时返回续期 `Set-Cookie`，浏览器 Cookie 过期时间被重置；页面保持打开期间不再因 24 小时 TTL 掉线。保活也在页面恢复前台时立即补查一次。
- **认证失效只切界面、不中断任务**：会话失效时 AuthGate 切换到登录界面并展示原因，正在后台运行的 Agent 任务继续执行；重新登录后可恢复观察。
- **会话持久化完成语义**：
  - 登录响应返回前，Session 已原子写入磁盘；写盘失败则删除内存会话并返回错误，不会出现「登录成功但重启即丢」。
  - 登出响应返回前，撤销结果已落盘；失败明确报错。
  - 后台保活滑动续期仍异步写盘，不阻塞请求。
- **启动服务器停止时同步关闭内部静态资产服务**，消除端口残留与进程不退出问题。

## 修复

- 修复滑动续期 `Set-Cookie` 丢失：`createHttpRequest()` 的 Proxy Request 与 `withSessionRefresh()` 的原始 Request 身份不一致，`WeakMap<Request, string>` 写入与读取键不同，续期 Cookie 永远取不出；现在统一关联身份。参见 `src/server/routes.ts`、`src/server.ts`、`lib/pi-web-auth-route.ts`。
- 修复单元测试误重启真实服务：`tests/unit/src/update-command.test.ts` 的完整更新流注入假 `refreshService`，不再回退到真实的 `refreshRegisteredServiceAfterUpdate()`。运行测试前后已核对 systemd 服务 PID/InvocationID 无变化。
- 修复登录/登出对持久化结果的误报成功（见「新增与改进」）。

## 测试与工程化

- 新增真实 Bun 服务器回归测试 `tests/unit/src/server-session-refresh.test.ts`：登录取得 Cookie → 请求 `/api/auth/status` → 断言返回续期 `Set-Cookie` → 推进时间后仍 authenticated。该测试直接走 `startServer()`、`createHttpRequest()` Proxy、路由与 `withSessionRefresh()` 完整链路。
- 新增保活/认证检查单测 `tests/unit/lib/session-keepalive.test.ts` 与 SSE 断线回调断言：会话失效通知登录墙、网络错误不误判登出、有效会话不触发登出。
- 全量单测 920 项通过；`bun run typecheck` 通过。

## 兼容与安全

- 未改动任何 `/api/*` 路径、方法、状态码或 JSON 字段语义；`/api/auth/status` 响应结构不变。
- 产品命名空间保持断裂：`pi-web-x` 不读取、迁移或兼容旧 `pi-web:*` 浏览器标识；Pi 通用数据仍位于 `~/.pi/agent`。
- 默认仅监听 loopback。LAN 或反向代理部署必须使用 HTTPS，并使用浏览器访问认证或 `PI_WEB_X_PASSWORD`，或置于可信 VPN 后。
- Host/Origin 校验及 Host Runtime Environment 与 Project Command Environment 的隔离保持不变。
- 无依赖保留/替代变更，`docs/maintainers/runtime-substitution-matrix.md` 无需同步更新。
