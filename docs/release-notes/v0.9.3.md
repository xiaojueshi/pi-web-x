# pi-web-x v0.9.3 发布说明

> 发布前按 [`../release.md`](../release.md) 核对制品、校验和与跨平台验收。

## 概要

v0.9.3 修复自更新检查在 GitHub API 限速下的失败：未认证的 GitHub API 按 IP 限速（60 次/小时），共享出口 IP 的配额被其他用户耗尽时返回 HTTP 403，导致 `pi-web-x update` 无法检查更新。本次新增 jsDelivr CDN 作为备用更新检查源，主源失败时自动降级，不再需要手动配置 `PI_WEB_X_UPDATE_URL`。

## 新增与改进

- **更新检查降级**：`pi-web-x update` 与 `/api/app-update` 的版本检查默认依次尝试 GitHub API 与 jsDelivr CDN 两个源；主源返回 403、超时或网络不可达时自动降级到备源，仅当两个源都不可达时才报错提示。
- **镜像格式兼容**：备源解析同时支持 GitHub API 的 `{ "tag_name": "v0.9.2" }` 与 jsDelivr 的 `{ "versions": [{ "version": "0.9.2" }, ...] }` 两种 JSON 结构；jsDelivr 版本数组乱序时取最大的稳定版本。
- **显式镜像语义不变**：设置 `PI_WEB_X_UPDATE_URL` 时仍只使用该源，适合指向内网镜像；不设置时自动获得双源降级能力。

## 修复

- 修复 `update` 在 GitHub API 返回 HTTP 403（共享出口 IP 的未认证限速配额耗尽）时直接失败的问题。

## 兼容与安全

- 产品命名空间保持断裂：`pi-web-x` 不读取、迁移或兼容旧 `pi-web:*` 浏览器标识；Pi 通用数据仍位于 `~/.pi/agent`。
- 默认仅监听 loopback。LAN 或反向代理部署必须使用 HTTPS，并使用浏览器访问认证或 `PI_WEB_X_PASSWORD`，或置于可信 VPN 后。
- Host/Origin 校验及 Host Runtime Environment 与 Project Command Environment 的隔离保持不变。
- 未改动任何 `/api/*` 路径、方法、状态码或 JSON 字段语义；`/api/app-update` 仅在源全失败时维持原有的“无更新”降级行为。
- 无依赖保留/替代变更，`docs/runtime-substitution-matrix.md` 无需同步更新。

## 构建与制品

- 构建环境：Bun `1.4.0`。
- 制品目标：darwin x64/arm64、linux glibc x64/arm64、linux musl x64/arm64、windows x64/arm64。
- Draft Release 必须包含八个 `pi-web-x-*` 二进制、`pi-web-x-assets-0.9.3.tar.gz` 及 `SHA256SUMS`。
- GitHub Actions 在推送 `v0.9.3` 后自动创建 Draft Release；确认制品与校验和后发布。
