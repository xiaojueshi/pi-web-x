# pi-web-x v0.10.0 发布说明

> 状态：**Released**。本文是已发布版本的冻结归档；发布流程见 [`../release.md`](../release.md)。

## 概要

v0.10.0 是一个功能版本（SemVer minor），围绕「Agent 与用户在 Web 端的高质量交互」新增两个内置工具，并升级 pi SDK 至 0.85.0：

1. **内置 `ask_user` 提问工具**：Agent 在需要澄清/选择/偏好输入时直接向用户提问，无需安装任何第三方插件。配套 Codex 风格的内联提问卡片（渲染在消息流底部，不再遮挡历史），支持单选/多选、选项搜索、自由输入。
2. **内置 `todo` 工具与三层进度可视化**：Agent 用 todo 工具拆解多步任务，用户随时能看到当前进度——顶部工具栏 TODO 按钮（带 n/m 徽标）、统一下拉面板（进度条 + 勾选列表）、消息流内每次操作的快照卡片。与社区 todo 插件数据格式完全兼容，旧会话无需迁移。
3. **pi SDK 升级至 0.85.0**，并修复升级引入的兼容性崩溃；同时修复 SSE 重连重放导致提问卡片状态丢失的用户可感知缺陷。

## 新增与改进

### 内置 ask_user 提问工具（此前：需安装第三方插件；现在：开箱即用）

- **改动前**：Web 端没有内置提问能力，Agent 想向用户提问需自行安装第三方 ask_user 扩展，且各扩展的 UI 呈现不统一；提问以模态对话框呈现，会遮挡聊天历史。
- **改动后**：`ask_user` 作为内置工具随每个会话自动注册（`lib/ask-user-extension.ts`），提供三类交互——纯文本问题、单选/多选（结构化选项含 label 与补充说明）、可关闭的自由输入。提问卡片内联渲染在消息流底部，支持选项搜索过滤（选项超过 6 项自动出现搜索框）、"其他"自由输入、Enter 提交、Esc 取消；卡片出现时自动滚动到底部。
- **冲突处理**：若用户已安装第三方同名 `ask_user` 扩展，内置版自动胜出——仅剥离第三方的 ask_user 工具，其扩展的其它工具不受影响，冲突诊断被清除。
- **入口**：聊天页面消息流；Agent 侧工具名为 `ask_user`。

### 内置 todo 工具与三层进度可视化（此前：状态只在消息流文本里；现在：进度常驻可见）

- **改动前**：todo 能力依赖社区插件（`~/.pi/agent/extensions/todo.ts`），Web 端只能以普通工具调用文本查看结果；想了解当前进度需要翻聊天记录找最近一次工具输出。
- **改动后**：`todo` 工具（list/add/toggle/clear 语义与社区插件完全一致）成为内置能力，状态快照存入工具结果的 details——分支/回溯后列表自动正确，旧会话的历史工具结果可直接渲染，无需任何数据迁移。可视化分三层：
  - **顶部工具栏 TODO 按钮**：位于「工具」按钮右侧，样式与工具栏统一（激活态 accent 顶边高亮）；按钮直接带 `n/m` 进度徽标，有待办未完成时图标高亮，不开面板即可看到进度。
  - **统一下拉面板**：点击 TODO 按钮打开，与 系统/工具/分支 面板同一互斥与定位机制、同一 `--bg-panel` 配色；内容为进度条 + 逐项勾选列表（已完成项绿色 ✓ 删除线置灰，未完成项 ○），无待办时显示空态。
  - **消息流快照卡**：每次 todo 操作在消息流中留下常显的进度卡片（进度条 + 勾选状态），展开工具调用仍可查看原始文本；历史消息同样可渲染。
- **数据通道**：最新快照由 ChatWindow 经 `onTodoChange` 回调上报 AppShell（与 `onSessionStatsChange` 等现有通道模式一致）；流式输出期间 `messages` 引用不变，不会逐 token 重算。
- **冲突处理**：与 ask_user 相同的 preferHost 机制，内置 `todo` 自动顶替第三方同名工具。
- **入口**：顶部工具栏 TODO 按钮；聊天页面消息流；Agent 侧工具名为 `todo`。

## 修复

### SSE 重连重放清空提问卡片状态（用户可感知：不再需要"一直重新选择"）

- **改动前**：服务端 `onEvent()` 会在每个新 SSE 监听器接入时重放未答复的提问请求（用于页面刷新后恢复提问卡片）。SSE 断线重连（网络抖动、睡眠唤醒、移动端切后台返回）会再次投递同一个 `extension_ui_request`，客户端无条件替换提问卡片对象，触发卡片状态重置——已选中的选项、输入中的内容全部丢失；重连反复发生时用户需要一直重新选择，带输入框时键盘焦点也一并丢失。
- **改动后**：客户端按请求 id 去重（`extensionDialogIdRef`）——同 id 的重复投递保留现有卡片，仅真正的新请求替换并滚动；用户答复后清除 id 记录，下一次提问正常视为新请求。
- **入口**：聊天页面内联提问卡片（所有扩展 UI 的 select/confirm/input/editor）。

### pi SDK 0.85.0 兼容修复

- **改动前**：升级 SDK 0.85.0 后服务无法启动——SDK `dist/main.js` 重导出 `experimental/server.js`，后者引用未在上游声明依赖的 `@earendil-works/pi-server`，导入即抛 `Cannot find module`；同时 0.85.0 的 `Theme` 构造函数新增 fallback 色键（`scrollbarTrack ?? muted`、`scrollbarThumb ?? text`），`PlainTextTheme` 缺键导致 `fgAnsi(undefined)` 崩溃。
- **改动后**：宿主侧补充 `@earendil-works/pi-server@0.85.0` 直接依赖；`PlainTextTheme` 补齐 `muted`/`text` 占位键；资产清单随 0.85.0 内置资产变化重新生成。
- **入口**：服务启动、TUI 主题初始化。

## 兼容与安全

- **上游依赖基线**：pi SDK 统一升级至 `0.85.0`（`pi-agent-core`、`pi-ai`、`pi-coding-agent`、`pi-tui`），新增宿主直接依赖 `pi-server@0.85.0`（补上游打包遗漏，非运行时替代）。构建环境 Bun `1.4.0`。
- **命名空间**：`pi-web-x` 命名空间与旧 `pi-web:*` 保持不兼容；Pi 通用数据仍位于 `~/.pi/agent`，无迁移变更。
- **API**：未改动任何 `/api/*` 路径、方法、状态码或 JSON 字段语义；扩展 UI 通道为向后兼容扩展（`select` 请求新增可选字段 `multiSelect`/`allowFreeform`/`context`，响应 `value` 从 `string` 放宽为 `string | string[]`，旧客户端字段仍有效）。
- **默认监听**：仍仅 loopback；LAN/反向代理部署要求与 v0.9.4 一致（HTTPS + 认证）。
- **Host/Origin 校验**、Host Runtime Environment 与 Project Command Environment 的隔离保持不变。
- 无依赖保留/替代变更，`docs/maintainers/runtime-substitution-matrix.md` 无需同步更新。
