# pi-web-x v0.10.1 发布说明

> 状态：**Released**。本文是已发布版本的冻结归档；发布流程见 [`../release.md`](../release.md)。

## 概要

v0.10.1 是一个修复版本，解决 v0.10.0 发布后暴露的自更新检查缺陷：**发版后 `pi-web-x update` 仍提示"当前已是最新版本（0.9.4）"**。

根因是更新检查把未经认证的 GitHub API 当作主源。`api.github.com` 的未认证配额仅 60 次/小时且**按出口 IP 计**——共享出口（VPS、VPN、运营商 CGNAT）下配额常被同 IP 的其他用户耗尽而返回 HTTP 403；随后静默降级到 jsDelivr CDN，而 jsDelivr 的版本索引有几分钟到几小时的延迟（v0.10.0 发布后索引仍返回 0.9.4），两个因素叠加导致 update 误报"已是最新"，且用户完全无法感知经过了哪个源。

## 修复

### 自更新检查主源改为 302 重定向解析（用户可感知：发版后 update 能立即发现新版本）

- **改动前**：主源为 `https://api.github.com/repos/xiaojueshi/pi-web-x/releases/latest`（未认证，60 次/小时/出口 IP）。共享出口 IP 下频繁 403，静默降级 jsDelivr；jsDelivr 索引延迟期间返回旧版本，update 报告"已是最新版本"——与刚发布的版本不符，用户需要等待或反复重试。
- **改动后**：主源改为 `https://github.com/xiaojueshi/pi-web-x/releases/latest/download/SHA256SUMS` 的 **302 重定向解析**——`releases/latest/download/<file>` 会 302 到带 tag 的下载地址（`/releases/download/vX.Y.Z/SHA256SUMS`），从 `Location` 头提取最新 tag。该端点走 github.com 静态下载域，**不经过 API、无配额限制**，与 update 实际下载发布物同域；使用 `redirect: "manual"` 只取第一跳，不真正下载文件。
- **源优先级**：GitHub 302 重定向 → jsDelivr CDN（免配额，索引有延迟）→ GitHub API（实时，限速，降为最后兜底）。`PI_WEB_X_UPDATE_URL` 显式镜像语义不变（设置后仅使用该源，适合内网镜像）。
- **降级可感知**：降级发生时 update 命令输出明确提示行（例如"注意：主要更新源不可达（…），版本信息来自 jsDelivr CDN。"），不再静默换源；用户能判断版本信息的可信度。
- **入口**：`pi-web-x update` / `pi-web-x update --check`；`/api/app-update` 响应新增可选字段（`source`、降级摘要），路径、方法与既有字段语义不变。

## 兼容与安全

- `/api/*` 路径、方法、状态码不变；`/api/app-update` 响应仅新增可选字段（向后兼容）。
- 产品命名空间保持断裂：`pi-web-x` 不读取、迁移或兼容旧 `pi-web:*` 浏览器标识。
- 默认仅监听 loopback。LAN 或反向代理部署必须使用 HTTPS，并使用浏览器访问认证或 `PI_WEB_X_PASSWORD`，或置于可信 VPN 后。
- Host/Origin 校验及 Host Runtime Environment 与 Project Command Environment 的隔离保持不变。
- 无依赖变更，无依赖保留/替代变更，`docs/maintainers/runtime-substitution-matrix.md` 无需同步更新。
- 上游基线与 v0.10.0 一致（pi SDK `0.85.0`，构建环境 Bun `1.4.0`）。

## 测试与工程化

- 新增更新检查主源单元测试：302 `Location` 解析（含非稳定 tag 拒识、无 `releases/download` 路径的 Location 拒识）、降级摘要断言（命中 jsDelivr 时摘要包含前置源失败原因且不再请求 GitHub API）、显式镜像源字段断言。
- 更新 `update` 命令完整流测试：fakeFetch 补 302 重定向分支，与生产源优先级一致。
- 全量单测 **942 项通过**；`bun run lint` 通过（0 error）；`bun run typecheck` 通过；真源实测 302 主源命中返回 `0.10.0`（未触碰 GitHub API）。

## 构建与制品

- 构建环境：Bun `1.4.0`。
- 制品目标：darwin x64/arm64、linux glibc x64/arm64、linux musl x64/arm64、windows x64/arm64（八个 Bun 编译单文件二进制）。
- Draft Release 必须包含八个 `pi-web-x-*` 二进制、`pi-web-x-assets-0.10.1.tar.gz` 及 `SHA256SUMS`。
- GitHub Actions 在推送 `v0.10.1` 后自动创建 Draft Release；确认制品与校验和后发布。
