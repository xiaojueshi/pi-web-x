# pi-web-x v0.11.2 发布说明

> 状态：**Draft**（发布后冻结为 Released）。发布流程见 [`../release.md`](../release.md)。

## 概要

v0.11.2 是一个修复版本，集中解决 v0.11.1 发布后暴露的两类用户可感知缺陷：

1. **侧边栏会话列表「加载中...」仍可能常驻**：v0.11.1 的并发计数器方案残留了一个 loadId 守卫，最常见的加载时序下加载态照样永久卡住（列表数据正常，但「加载中...」不消失）。
2. **连接安全提示误报「此连接尚未启用 Web Access Authentication」**：已设置密码且已登录的浏览器仍持续显示该提示；且本机回环访问（无跨设备风险）也会显示。

两者均为前端缺陷，不涉及服务端 API 行为变化。

## 修复

### 侧边栏「加载中...」仍可能常驻（用户可感知：加载态如实反映加载状态）

- **改动前**：v0.11.1 引入的并发计数器在 `finally` 中仍要求 `loadId === sessionLoadIdRef.current` 才关闭加载态。最常见的时序是：挂载时初始 `loadSessions(showLoading=true)`（loadId=1）在飞行中被 running 轮询触发的后台刷新 `loadSessions(false, true)`（loadId=2）抢占；初始请求结束时计数已归零，但 loadId 失配，`setLoading(false)` 再次被跳过——加载态永久卡住。这正是 v0.11.1 发布后用户实测仍复现的原因。
- **改动后**：关闭加载态不再受 loadId 守卫。`setLoading(false)` 只关闭加载指示、不写列表数据，不存在覆盖问题；并发中的新 showLoading 请求由计数器 >0 保护，加载态不会被提前关闭。语义归纳为：**只有当所有「带加载态的请求」都结束后，加载态才关闭**。同时为 `/api/sessions` 的 fetch 增加 30 秒 `AbortSignal.timeout` 超时兜底，即使请求挂死，加载态最多持续 30 秒后消失（此时显示错误状态而非永久「加载中」）。
- **入口**：侧边栏会话列表（`components/SessionSidebar.tsx` 的 `loadSessions`）。

### 连接安全提示按认证初始化状态与访问地址显示（用户可感知：提示不再误报、本机不再打扰）

- **改动前**：提示组件 `PwaRegistration` 位于认证墙（AuthGate）之外，只在页面挂载时请求一次 `/api/auth/status`。若页面加载时恰好未登录（如会话过期后打开页面），之后在登录页登录成功——登录不触发整页刷新，认证墙原地切换视图——提示组件手里的认证状态永远停留在登录前，安全提示「此连接尚未启用 Web Access Authentication」一直挂着，尽管认证早已设置且用户已登录。另外，提示条件为「当前会话未认证」，导致局域网/本机登录页上也常驻该提示；而本机回环访问不存在跨设备窃听风险，提示文案本身（「在本设备以外访问时……」）对纯本机访问没有意义。
- **改动后**：
  - **状态实时化**：登录成功、首次设置密码成功时，认证墙派发新事件 `pi-web-x:auth-established`（`lib/session-keepalive.ts` 新增导出），`PwaRegistration` 监听后重新拉取 `/api/auth/status`；同时监听现有会话失效广播 `pi-web-x:auth-status` 同步失效状态。不扩展现有失效事件发送成功状态，因为 AppShell 收到该事件会重挂载认证墙子树，保活轮询/回前台时会造成频繁重刷。
  - **显示条件收窄**：仅当 **Web Access Authentication 未初始化（从未设置密码）** 且访问地址非本机回环时提示；或连接非 HTTP 安全上下文（PWA 能力不可用）时提示。密码已设置后，会话过期/未登录由认证墙登录页自行接管，不再算「连接安全问题」。局域网/其他地址在密码未设置时仍会提示（含登录页）——那正是提示真正要保护的场景。
- **入口**：底部 PWA 安全提示条（`data-pwa-notice="connection"`）。

## 变更与加固

- 无 API、无依赖变更。

## 兼容与安全

- `/api/*` 路径、方法、状态码、JSON 字段与 SSE 事件语义不变；`pi-web-x:auth-established` 为纯前端窗口事件，不经过网络。
- 产品命名空间保持断裂：`pi-web-x` 不读取、迁移或兼容旧 `pi-web:*` 浏览器标识。
- 默认仅监听 loopback。LAN 或反向代理部署必须使用 HTTPS，并使用浏览器访问认证或 `PI_WEB_X_PASSWORD`，或置于可信 VPN 后。
- Host/Origin 校验及 Host Runtime Environment 与 Project Command Environment 的隔离保持不变。
- 无依赖变更，`docs/maintainers/runtime-substitution-matrix.md` 无需同步更新。
- 上游基线与 v0.11.1 一致（pi SDK `0.85.1`，构建环境 Bun `1.4.0`）。

## 测试与工程化

- 全量单测 **1023 项通过**；`bun run typecheck`、`bun run lint` 通过。
- 放宽 `PwaRegistration` 源码断言测试中 `controllerchange` 监听的匹配（兼容多行排版），断言意图（更新需用户确认后生效）不变。
- 认证提示修复经隔离 HOME 真实服务器验证：未登录 `/api/auth/status` 返回 `authenticated:false`，登录后同接口返回 `authenticated:true`，服务端行为正确，缺陷确认为前端状态同步问题。
